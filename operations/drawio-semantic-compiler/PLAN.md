# Draw.io 图语义编译器实施计划

## 交付目标

实现独立的单输入入口 `drawio-compile SOURCE --out DIRECTORY`。同一份输入依次经过预处理、词法与语法分析、语义检查、IR 规范化和 XML 生成。输出包括可直接在 draw.io 打开的规范化 XML、带版本号的 IR、原始位置和 cell 映射、以及验收报告。既有 `drawio-compare` 可用于故障定位和报告。

全量范围是开跑时确认并冻结的当前可编辑数据集。原始文件按案例保留，交付每个案例的编译产物和证明。另抽 50 条，让 DPSK Harness 从已编译 XML 生成大幅扰动的等价输入，再用同一入口独立编译并验证它们收敛回对应的规范化 XML。

## 编译流水线

1. **预处理。** 识别裸 `mxGraphModel`、多页 `mxfile` 和 draw.io 压缩页，解包到逐页输入。区分 XML 结构中的空白和图形内容中的空白。保留文本、HTML、公式、样式、资源、链接和自定义数据。记录压缩页和解包后页内位置的对应关系。
2. **词法与语法分析。** 复用可靠的 XML lexer/parser，取得元素、属性、文本和源位置。对 draw.io 专有的样式串、几何点、引用和对象包装做独立解析，覆盖 Unicode、转义、重复样式键和内嵌资源。检查 XML 错误，保留能指到页和原 cell 的诊断。使用原生 draw.io 模型和解码器做交叉验证。
3. **构建并验证图语义 IR。** 表达页、层、绘制顺序、可选中分组、父容器、节点、端口、有向边及自由端点、路径与控制点、标签、表格、有效样式和资源。区分局部几何与页面坐标。绑定边包含明确端点引用，自由边包含明确几何。验证唯一身份、引用解析、父子无环、有限几何、变换、层顺序及对象类型约束。保留语义相关的扩展，给出证据不足的具体项。IR 持久化，带到原始 XML 的映射。
4. **在 IR 上规范化。** 以规则及前置条件驱动，逐步消除无意义包装、声明、空白、默认属性、等价表达和可证明冗余的坐标容器。保留命名锚点、真实可编辑分组、端口、绘制顺序和资源语义。按规范化语义确定短 ID 和记录顺序，重写所有引用。XML 节点存放顺序、命名或透明嵌套变化在等价时应得到同一 IR。视觉一致但可编辑行为有差异的对象保留各自的语义。
5. **从 IR 生成规范化可编辑 XML。** 用同一套确定性的语法、数值、属性顺序和转义规则生成紧凑 XML。读取生成件重建 IR，确认语义、引用和内容完整。将最简明确为在保留指定绘制和编辑语义的输出语法及已验证变换集合下，删减到固定点。建立规则覆盖清单及可删减性审计，记录尺寸和任何必须保留的语义信息。对全局最短的主张须有明确等价关系和证明。

可直接复用 `conversion/drawio_compare/model.py` 的解包入口、`native.js` 和 `runtime.py` 的官方渲染、坐标和编辑探针。用 `compare.py` 和 Patch MSE 定位失败，规范化和语义验证由新编译器完成。实现可根据库和真实数据的行为调整。

## 逐件验收

使用 计算节点 上固定的官方 draw.io 和 Chromium、固定的字体和资源、共享页面坐标与栅格尺寸。每件原 XML 与生成 XML 都由原生编辑器独立打开和渲染，对每页解码后的像素作精确比较，留存原件和生成件像素 SHA-256、画布映射、编译和重开状态。多页逐页对齐。资产缺失或渲染失败要有具体记录。对于使用相同渲染协议的现有配对图，另核对来源和像素证据。

用单件可编辑性门槛检查图元及其语义完整性，执行适用的节点移动、文本编辑、连接端点跟随、容器和表格操作以及还原。对原件和生成件比较适用的行为。测试同像素但自由边与绑定边编辑行为不同的对照。验证二次编译字节不变，独立进程和任务分片顺序产生相同结果。保留可复现的首个失败和阶段证据。

## 执行顺序和退出条件

1. **冻结当前数据。** 核对发布方当前指针、所含子集和去重规则，以稳定案例 ID 与输入 SHA-256 建立全量清单。核对数据集版本和案例总数。原件留在当前数据目录，编译产物、队列、分片和报告写入本次 计算节点 工作区。
2. **实现并跑最小测试。** 建立编译入口和可重放测试。覆盖压缩、多页、用户对象、相对端口、弯折边、重叠 Z 序、不可见编辑关系、表格、数学标签，以及不合法引用、颜色或几何错误等能判定的规则。检查失败的来源定位和最简规则。
3. **用真实样本压测后运行全量。** 按格式、布局、语义特征和来源抽样，核对正常入口的真实渲染和编辑。将其扩展到冻结的每条记录，限制并行数、可断点续跑。每条按输入和编译器版本写独立状态。至少两次核验真实编译、渲染与成功产物增量，处理任何失败并重验。最终审计清单逐件闭合，所有原始 SHA-256 保持一致，原件像素与编译后像素逐页一致。
4. **DPSK 50 条强扰动。只有这 50 条的扰动需要 DPSK，全部编译、渲染与验证均由确定性程序执行。** 从已验收的输出中固定种子分层选 50 条，单独留存挑选清单。交给本地 DPSK Harness 写或执行独立的变体生成器，数据转换和验证在 计算节点 执行。扰动包含大范围 ID 重命名及引用重写、交换无语义的 XML 声明顺序、插入并补偿多层坐标容器，组合适用变换。对每条保留具体变换和实际覆盖，验证变体像素与基准相同、约定的编辑行为成立。随后只给编译器变体 XML，要求 50 条都回到该案例的规范 XML 字节、IR、像素和可编辑行为。保留成对的变化反例以核对验证能识别语义差异。
5. **发布。** 源码、运行入口、DPSK 变体生成与验证脚本、配置和故障复现步骤提交并推送到 `shaoshitong/xml_pipeline` 的本任务分支。核验 GitHub 与 计算节点 源码 SHA、运行版本、全量清单、产物哈希和 50 组报告。向用户交付审计摘要，完整数据留在 计算节点。

任何无法解释的结构、编译失败、像素变化或缺失的可编辑性证明，都必须留在分母中继续处理。

## Claude Code 和计算接口

- 让本地 `claude-sandbox` 用 **Claude Fable 5.2** 执行此计划。确认实际模型标识。仅当当前账号明确额度耗尽，核验当前会话和已完成工作后，用 `claude-sandbox2` 的同一模型从共享工作区和持久检查点继续。保持一次一条工作链，保留原会话和代码历史。
- 给沙箱安装 计算节点 工作所需的 MCP，先复用已配置的 `lab-host` 访问能力，核对实际提供的工具和节点。沙箱一律使用 `remote_cc` 中的中性资源名 `lab_4090_3`。用只读调用确认 `lab_4090_3` 的远端命令执行成功，再通过该接口部署并执行任务脚本。需要时以任务工作区内的请求和回执衔接宿主校园 SSH。另用本地 DPSK Harness 的命令行入口完成第 4 步。实测过的接口、会话和进展留记录。
- Mac 和沙箱做代码编辑与任务控制。数据处理、渲染、数据集测试和完整日志都留在 计算节点。Claude Code 沿已有固定 VPS 路由工作，计算节点 用已有校园通道。使用已配置的认证与隔离方式。工程凭据留在各自原有位置。所有部署与试验集中在本任务工作区。
- 第一批工作从实现单输入编译和能证明其经过 IR 的真实样例开始。落地后就提交检查点，再按上述步骤推进。每次交接记录本次分支、提交、运行路径、已完成的真实证据和下一条可执行命令。
